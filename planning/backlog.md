## Bugs

- [ ] **uphill jump lock** — when jumping against an uphill slope, the player can land in a state where `jump` never re-triggers: the character controller reports ground contact but the slope normal keeps the jump cooldown active. Suspected cause: Rapier's ground-contact normal threshold in the character controller or the jump cooldown not resetting when sliding contact ends. Reproduce: 3rd_person_game_demo, run toward any hill and spam jump while ascending.
- [x] **`PrefabComponents` silently drops unknown fields** — added `#[serde(deny_unknown_fields)]`; RON parse now fails with a clear field name on typos or unknown fields; two regression tests added.

- [ ] **Inventory & item system** — RON-defined item catalog (`items/items.ron`) containing `ItemDef` entries (key, display name, icon texture key, stackable, max_stack, weight, tags); `Inventory` component on entities holds a list of `(item_key, count)` stacks up to a designer-set `max_slots`; player bag = `Inventory` on the player entity; world containers (chests, crates) = scene objects with an `Inventory` component and an `OpenContainer` interaction; **actions**: `AddItem(entity, key, count)`, `RemoveItem(entity, key, count)`, `TransferItem(from, to, key, count)`, `OpenInventory`, `CloseInventory`; - [ ] **Quest system** — RON-defined quest catalog (`quests/quests.ron`) containing `QuestDef` entries; each quest has a key, title, description, optional `prerequisites:` (list of quest keys that must be completed first), a list of `QuestObjectiveDef` entries, and a `rewards:` block; **objective types**: `KillCount(prefab_key, count)` tracks entity deaths matching a prefab key, `Collect(item_key, count)` satisfied when the player's inventory contains enough, `ReachLocation(trigger_zone_key)` satisfied when the player enters a named trigger zone, `TalkTo(npc_key)` satisfied by a `dialogue.ended:{id}` event, `Custom(event_pattern)` satisfied by any matching pipeline event — designer-extensible without engine changes; `QuestLog` resource on the player tracks per-quest state (`Inactive` / `Active` / `Completed` / `Failed`) and per-objective progress counters; **actions**: `AcceptQuest(key)`, `AbandonQuest(key)`, `CompleteObjective(quest_key, obj_key)` (for manual or event-driven completion), `FailQuest(key)`, `CompleteQuest(key)` (force-complete, skips objectives — useful for debug or cutscene grants); objectives with countable progress (KillCount, Collect) auto-advance their counter when the relevant event fires — no explicit `CompleteObjective` call needed for those types; a quest auto-completes when all objectives are satisfied if `auto_complete: true`, otherwise enters a `ReadyToTurnIn` sub-state requiring a `CompleteQuest` call (typically from a dialogue choice on the quest-giver NPC); **rewards** declared as a list of reward entries: `GiveItem(key, count)`, `GiveStat(stat_key, amount)`, `UnlockQuest(key)`, `RunActions([...])` for arbitrary pipeline actions — all dispatched through the existing action executor on completion; **conditions**: `QuestState(key, state)`, `ObjectiveProgress(quest_key, obj_key, min_count)`, `AllObjectivesComplete(quest_key)`; **events**: `quest.accepted:{key}`, `quest.objective_progress:{key}:{obj_key}:{count}`, `quest.objective_complete:{key}:{obj_key}`, `quest.ready_to_turn_in:{key}`, `quest.completed:{key}`, `quest.failed:{key}`, `quest.abandoned:{key}` — all flow into the rules pipeline so other quests, scenes, or NPC states can react; **quest-giver NPC integration**: `QuestGiverDef` on `PrefabDef` listing quest keys the NPC offers; the NPC automatically shows an indicator icon (available / in-progress / ready-to-turn-in) based on `QuestLog` state; clicking/interacting opens a dialogue tree with accept/turn-in choices; **quest tracker UI**: HUD panel listing active quests with their objectives and progress counts — declared as a `QuestTracker` UI node type in scene RON with designer-controlled position and max visible quests. **Requires a feature file before coding** — key design decisions: kill-count tracking (listen to a new `entity.died:{prefab_key}` event vs. a death hook in the NPC AI capability), whether `QuestLog` serialises cleanly for the save/load system, branching objective graphs (sequential vs. parallel vs. any-N-of-M completion), and how the quest-giver indicator icon is rendered (world-space billboard vs. nameplate integration). Soft dependency on inventory system for `Collect` objectives and item rewards; soft dependency on dialogue system for accept/turn-in flow; soft dependency on stat templates for stat rewards; soft dependency on save/load for quest log persistence across sessions.
- [ ] **Loot system** — RON-defined loot table catalog (`loot/loot_tables.ron`) containing `LootTableDef` entries; each table has a key and a list of `LootEntry` rows with `item_key`, `chance` (0.0–1.0), `min_count`, `max_count`, and an optional `quality` tag (`Common` / `Uncommon` / `Rare` / `Epic` / `Legendary`) used for icon border tinting in the loot UI; tables support two roll strategies declared per-table: `RollEach` (every entry is rolled independently, multiple items can drop) and `RollOne` (one entry is selected weighted by chance, used for tiered drop pools); tables can mix a guaranteed section (`chance: 1.0` entries always included) with a random pool; `LootTableRef(key)` field on `PrefabDef` links an entity to a table — on entity death the engine rolls the table automatically via the new `entity.died:{prefab_key}` event; world containers (chests, crates) also support `LootTableRef` — rolled once on first open; **loot bag**: rolled items are placed into a short-lived `LootBag` world entity (its own prefab key, despawns after `despawn_after_secs`) spawned at the dead entity's position — designer controls the bag mesh/icon via the prefab; `PickupLoot(entity)` action transfers the bag's contents to the player's inventory and despawns it; `auto_loot: true` flag on the scene or per-prefab skips the bag entirely and adds items directly to inventory on death; **actions**: `RollLootTable(table_key, target_entity)` for manually triggering a table (quest reward chests, scripted drops), `PickupLoot(bag_entity)`, `ClearLootBag(bag_entity)`; **events**: `loot.rolled:{table_key}`, `loot.item_dropped:{table_key}:{item_key}:{count}`, `loot.bag_spawned:{bag_entity}`, `loot.collected:{item_key}:{count}` — designers can hook `loot.item_dropped` to auto-complete quest collect objectives or play a fanfare; **loot UI**: when the player approaches a loot bag a panel lists its contents with item icons, quality colour borders, and a Take All button; individual items can be taken one at a time. **Requires a feature file before coding** — key design decisions: `entity.died` event architecture (death hook in NPC AI capability vs. a generic `OnDespawn` observer), whether nested tables (a `LootEntry` that references another table key for tiered pools) are in scope for v1, loot bag despawn timer source (scene default vs. per-prefab), and instanced vs. shared loot for future multiplayer compatibility. Hard dependency on inventory system for item storage; soft dependency on quest system for `loot.item_dropped` → collect-objective auto-advance; soft dependency on equipment system so equippable items can appear in loot tables.

### Performance
- [ ] **Extend pipeline warmup to Text2d and UI pipelines** — spawn hidden warmup entities for `Text2d` and UI `Node` at scene load to pre-compile the 2D/UI GPU pipelines, eliminating WASM frame spikes on first text/UI render; design: `planning/features/pipeline_warmup_2d_ui.md`
- [ ] **Discrete LOD steps for depth-scaled label font sizes** — snap `base_font_size * scale` to a small fixed set (e.g. 100 %, 75 %, 50 %, 25 %) instead of rounding to every integer; bounds atlas slot count to ~4 per label regardless of depth range, at the cost of a slight stepping artefact on slow zoom. Integer rounding + 0.5-threshold guard already fix the per-frame atlas upload problem; this is a further atlas-memory micro-optimisation.
- [x] Staggered entity spawning — `PendingEntitySpawns` queue drains at `SPAWNS_PER_FRAME = 2`/frame via `drain_spawn_queue_system`; spreads WebGPU pipeline compilations across frames for wave spawns
- [ ] **Scene transition material cache** — `scene_loader` rebuilds all materials in the asset catalog on every `LoadScene`, including materials already built for the previous scene; cache built handles per-project in a persistent resource and only rebuild when the catalog key set changes; estimated 50–200 ms saving per transition on large projects (`scene_loader.rs` material rebuild block)
- [ ] **WASM terrain generation first-frame stall** — `AsyncComputeTaskPool` degrades to `block_on` on the main thread in WASM, causing 100–500 ms jank on first frame for large heightmaps; fix by splitting mesh generation across multiple frames (progressive tile-by-tile build) or pre-baking terrain meshes as GLB assets; requires `#[cfg(target_arch = "wasm32")]` code path (`terrain.rs` poll system)
- [x] **Particle mesh buffer recreation** — the pool renderer rebuilds full `Vec<[f32;3]>` vertex buffers and re-inserts mesh attributes every frame for every active particle group; replace with in-place attribute mutation (`Mesh::attribute_mut`) to avoid per-frame allocations and reduce GPU upload overhead; particularly impactful on WASM where buffer uploads block the main thread (`particle_renderer.rs`)
- [x] **Animation player entity lookup cache** — `animation_playback_system` recurses through the entity hierarchy every frame to locate the `AnimationPlayer` child; `AnimationController` already has a `last_player_entity` field — use it as a fast-path cache and only re-walk the tree on cache miss; reduces O(tree_depth) lookups to O(1) for the common case (`animation.rs`)
- [ ] **Per-frame collection allocations in hot systems** — `stat_modifier_system` (key clone Vec), `message_interpreter_system` (event Vec rebuilt each frame), and `player_movement_system` (input HashMap) each allocate new collections every frame; refactor to reuse pre-allocated collections via `.clear()` on a `Local` resource or avoid the intermediate collection entirely; WASM GC pressure is higher than native so the gain is larger there

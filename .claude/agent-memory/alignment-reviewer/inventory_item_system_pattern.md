Inventory & item system (introduced ~2026-06-20). Items defined in `items/items.ron` (`ItemCatalog`/`ItemDef`), referenced by `ProjectConfig.items_path: Option<String>`. Loaded via `ImplicitRonPlugin::<ItemCatalog>` + `project_loader.rs` (handle path) with `LoadedItemCatalog(None)` fallback when absent. Resources registered in lib.rs: `PlayerInventory`, `LoadedItemCatalog`, `LoadedInventoryUi`. SystemParam queries on `SceneStateParams` (action_executor) and `SceneV2Params` (scene_loader). `inventory_ui_system` in `Update`.

**What it gets right (positive reference):**
- Item data fully in RON; zero hardcoded items. `ItemDef` has proper `#[serde(default)]` + named default fns, `deny_unknown_fields`, and `ItemCatalog::validate()` with designer-facing error messages.
- `PlayerInventory` persists across scenes (Resource, like LoadedStats); container `Inventory` is a `LevelEntity` component cleared on scene load. Correct persistence split.
- `MerchantDef` is **NOT** a spawned component — `OpenShop(merchant_id)` resolves `PrefabKey` via SpawnRegistry then looks up `prefab.merchant` live from `LoadedPrefabCatalog`. So merchant works on ALL prefab kinds with no per-spawn-path wiring needed (immune to the [[prefab-marker-three-spawn-paths]] footgun). Stock is per-prefab in prefabs.ron. Good design.
- No capability pushes to ActionQueue — `inventory_ui_system` only reads `PlayerInventory` and writes `Text`. All mutation is in the executor.
- `AddItem`/`RemoveItem` emit namespaced `GameEvent::Trigger` (`inventory.added:{e}:{k}:{n}`, `inventory.full:{e}`, etc.) — designer-reachable for chaining.

**Three blockers found at introduction (check these on any inventory follow-up):**
1. **`rewrite_self`/`rewrite_target` omission** — `AddItem`/`RemoveItem`/`TransferItem`/`OpenShop` all take entity/spawn-ID `String` fields but were NOT added to either fn in message_interpreter.rs (fell to `other => other`). A behavior file using `AddItem(entity:"{self}",...)` or a rule using `{target}` silently misses. This is the canonical [[entity-targeted-action-pattern]] miss. `TransferItem` needs BOTH `from` and `to` rewritten.
2. **Composite/single-mesh `Inventory` miss** — `prefab.inventory` is inserted ONLY in `entity_spawner.rs::spawn_prefab_instance` (GLB-only). The composite-primitive branch (scene_loader.rs ~245) re-implements interactable/dialogue/trigger_zone/behavior/npc/stat_templates by hand but omits `inventory`. A `kind:Primitive` crate/chest with `inventory:` set gets no `Inventory` component → silent no-op. Classic [[prefab-marker-three-spawn-paths]]. (merchant is exempt — live lookup, no component.)
3. **CLI `action_kind` exhaustive match** — `query.rs::action_kind` (~line 556) is an exhaustive `match` with no wildcard. The 7 new variants were not added → `cargo check -p ironhold_cli` fails to compile. This is the workflow-step-4 CLI break.

**Warnings at introduction:** no example project ships items.ron / InventoryPanel / merchant (grep `assets/projects` found zero usages); no docs in `docs/` mention the feature (`docs/20_data_formats.md` etc. have no items/inventory/merchant); `ItemDef.icon` is parsed but unused ("future icon rendering") — dead designer-facing field.

**Follow-ups reviewed clean (2026-06-20):**
- `ToggleInventory` action — added to all 3 touchpoints (actions.rs variant + doc, action_executor.rs match arm reads/flips `inventory_panel_q` Visibility, query.rs action_kind). Targets panel by node TYPE (singleton query), NOT spawn-ID, so it is immune to the rewrite_self/target footgun — no interpreter substitution needed. Mirrors OpenInventory/CloseInventory. Wired in 3rd_person_game_demo via `global_key_bindings: {"KeyI": "toggle_inventory"}` → `ui.button_pressed:toggle_inventory` → `[ ToggleInventory ]`. Shipped example present.
- Icon-sheet support — `InventoryPanelDef.icon_sheet`(catalog key)/`icon_cols`/`icon_rows`/`icon_cell_size` + `ItemDef.icon_index`. All resolution goes through `asset_catalog.textures.get(key)` (TextureAtlasLayout::from_grid) and `LoadedItemCatalog` for index — NO fabricated paths, NO hardcoded fallback. Missing item key → `.unwrap_or(0)` index (acceptable). scene_loader pre-resolves atlas before with_children (mutable-borrow pattern, same as ActionBar). `inventory_ui_system` updates atlas index + Visibility on `PlayerInventory` change with change-detection guards. `InventorySlotIconMarker` is a UI marker only, not a spawn-path marker — single InventoryPanel spawn site, so the 3-spawn-path footgun does NOT apply. `ItemDef.icon` (standalone texture key) is STILL dead/unused — distinct from `icon_index`; only `icon_index` is wired.
- The icon-atlas pattern (sheet catalog key + cols/rows/cell_size + per-item index) is shared by ActionBar (`StatRadarDef`/`ActionBarDef` neighbors) and InventoryPanel — same `TextureAtlasLayout::from_grid` + pre-resolve-before-closure shape. When reviewing new atlas-icon UI, check: catalog-key lookup (not path), atlas pre-resolved outside `with_children`, change-detection guard on index writes.

**Container panel follow-up reviewed (2026-06-21):** `OpenContainer(String)`/`CloseContainer`/`TakeAllFromContainer` + `ContainerPanelDef` (UiNodeDef variant, all 5 helpers impl'd) + `LoadedContainerUi` resource + `container_ui_system` (no ActionQueue — reads `Inventory`, writes Text/ImageNode/Visibility, all compare-then-write guarded; same shape as `inventory_ui_system`). `InventoryContainerDef` gained `initial_items: Vec<InitialItemEntry>` + `max_slots.max(4)` clamp. Findings:
  - **BLOCKING-class spawn-path inconsistency**: the THREE inventory spawn paths diverge. entity_spawner.rs:77 (GLB) ✓ `.max(4)`+`initial_items`; scene_loader.rs:383 (composite primitive `model:""`+children) ✓ both; scene_loader.rs:658 (**single-mesh primitive**) does `Inventory::new(inv_def.max_slots)` — NO `.max(4)`, NO `initial_items`. A `kind:Primitive` chest with no children + initial_items gets empty inventory + unclamped slots. Shipped `chest_01` is `kind:Prop` (GLB path) so the example works, masking the bug. Canonical [[prefab-marker-three-spawn-paths]] miss — exactly the composite-vs-single split this memory's blocker #2 warned about, but this time it's the single-mesh branch that's wrong.
  - **`OpenContainer` missing from rewrite_self AND rewrite_target** (message_interpreter.rs). Takes a container spawn-ID `String`, falls to `other => other`. `OpenContainer("{self}")` in a behavior file or `OpenContainer("{target}")` in a rule silently no-ops. Classic [[entity-targeted-action-pattern]] omission. `OpenShop` IS in both — direct precedent. `CloseContainer`/`TakeAllFromContainer` take no entity arg so correctly absent.
  - **`TakeAllFromContainer` reads active-container from `LoadedContainerUi` resource, not an action param** — this is ALIGNED. Mirrors `EndDialogue`/`AdvanceDialogue`/`CloseShop`/`CloseInventory` which all operate on the implicitly-open singleton panel. A container is a modal singleton (one open at a time), so resource-state is the right model; adding `TakeAllFromContainer{entity}` would be redundant and could desync from what the panel shows. Do NOT recommend parameterizing it.
  - Hardcoded designer-facing strings in ContainerPanel header: title `"Chest"`, take-all `"Take All"`, close `✕` (scene_loader ~2154/2262/2173). WARNING only — InventoryPanel/ShopPanel hardcode their titles too (no `title` field on any panel def), so consistent pre-existing gap, not a regression. `ContainerPanelDef` has no `title` field.

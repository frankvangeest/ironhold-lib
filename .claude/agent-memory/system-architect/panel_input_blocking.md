"No click-through" for open panels (inventory/shop/container) must address TWO fully independent input paths. There is no single UI node or guard that covers both. Two prior implementation attempts failed by conflating them (verified against bevy_ui 0.18.0 source + ironhold_core at this date).

**Path 1 — UI buttons.** `button_system` (lib.rs ~342) reads `Query<(&Interaction,...), (Changed<Interaction>, With<Button>)>`. `Interaction` is written by Bevy's `ui_focus_system` (bevy_ui/src/focus.rs), driven directly by `ButtonInput<MouseButton>` + `UiStack`. This path does NOT use the bevy_picking backend (`UiPickingPlugin`/`Pickable`/`should_block_lower` in picking_backend.rs) — that backend writes separate observer events `button_system` never reads. So `Pickable` is irrelevant here.

**Path 2 — world-space targeting.** `click_select_system` (targeting.rs ~98) and `tab_targeting_system` (~151) read `ButtonInput<MouseButton>`/`ButtonInput<KeyCode>` directly and project entity origins to screen space. Bypasses UI focus AND picking entirely. Only a code guard reading `LoadedInventoryUi.panel_open` can block it. `click_select_system` already has the guard; `tab_targeting_system` does NOT (gap).

**How a UI node blocks Path 1 (focus.rs, bevy_ui 0.18.0):** `ui_focus_system` runs in TWO loops. Loop 1 gathers `hovered_nodes` = every node whose ComputedNode rect contains the cursor AND `inherited_visibility==true`, in `UiStack` (z) order bottom→top. Loop 2 iterates `hovered_nodes` top→bottom (`.rev()` was already applied) and: sets `Interaction` ONLY on nodes that have an `Interaction` component; then `match focus_policy.unwrap_or(&FocusPolicy::Block)` — `Block` => `break`, `Pass` => continue. So `FocusPolicy::Block` is the DEFAULT when no `FocusPolicy` component is present. A bare `Node` blocks lower nodes (default Block + gets added to hovered_nodes even without Interaction).

**CRITICAL child-button fact (verified focus.rs 0.18.0):** `Block` on a PARENT panel root does NOT prevent the parent's own child buttons from being Pressed, because child buttons drawn on top of the panel sit HIGHER in `UiStack` than the panel root. Loop 2 walks top→bottom, so the child button is reached and Pressed BEFORE the parent root's Block causes the `break`. The Block on the parent only stops iteration from reaching nodes BELOW the parent in z (i.e. base-scene buttons). So: panel root `FocusPolicy::Block` + child buttons with `Button`/`Interaction` = child buttons work, base-scene buttons beneath the panel rect are blocked, base-scene buttons OUTSIDE the panel rect are untouched (never entered hovered_nodes). This is why per-rect blocking via panel-root Block is correct and the full-screen blocker is unnecessary. NOTE: a node with NO `Interaction` component still participates in the Block/break decision (the match runs regardless) — so the panel root does not need `Interaction` to block; but click_select_system's guard reads `Query<&Interaction>` for `Pressed`, so IF you want the panel root itself to register Pressed (to suppress world targeting via that guard), it DOES need an `Interaction` component. A child button being Pressed also satisfies that guard.

**Why the overlay backdrop blocks but the imperative panel-blocker did not (the key non-obvious fact):** both are byte-identical bare `Node` 100%x100%. The backdrop is spawned in `spawn_scene_v2` (ordered `.before(message_interpreter_system)`) at SCENE-LOAD time, so by the next frame it has a `ComputedNode`/layout and is a stable long-lived node. The blocker was spawned in `action_executor_system` (Update) via deferred `commands` AT ACTION TIME — on the frame created it has no `ComputedNode` (layout runs in PostUpdate), so `ui_focus_system` skips it (size==ZERO / query miss). Spawn-at-action-time races layout; spawn-at-scene-time does not.

**SUPERSEDED design decision (2026-07-01): per-rect blocking, NOT full-screen blocker.** Frank's requirement: click-through blocked ONLY within the panel's window region — a button in a non-overlapping corner must stay clickable. The full-screen blocker (GlobalZIndex 98, FocusPolicy::Block, added ~this date) violates this: it covers the whole screen so it blocks the dance button even when the shop panel doesn't overlap it. REMOVE the full-screen blocker. Instead put `FocusPolicy::Block` directly on each of the 3 panel roots (InventoryPanel/ShopPanel/ContainerPanel, already at GlobalZIndex(99)). Rect containment is then per-node and free. Remove `panel_blocker: Option<Entity>` from LoadedInventoryUi and the blocker spawn block in scene_loader.rs (~line 1319-1355) and the 6 executor visibility-toggle arms.
- Path 1: `FocusPolicy::Block` on panel root. Child buttons work (see child-button fact above). Base-scene buttons under the rect blocked; outside the rect untouched. Panel root should ALSO carry `Interaction::default()` so a click on panel dead-space (not on a child button) still registers Pressed → suppresses world targeting via Path 2 guard. Without Interaction on the root, clicking panel background (not a button) would fall through to world targeting.
- Path 2 (world targeting): `click_select_system` already guards on `ui_interactions.iter().any(|i| *i==Pressed)`. With panel-root Block+Interaction: click in rect → panel root or child Pressed → suppressed; click outside rect on a monster → nothing Pressed → proceeds. Correct per-rect. Update the stale comment in click_select_system that references "full-screen panel blocker (GlobalZIndex 98)".
- Keyboard/physics paths (Tab targeting, F-key interactable, collectible walk-over) are NOT position-based → keep the `panels_open > 0` guard (already in tab_targeting_system:170). These should stay fully blocked whenever any panel is open. Keep `panels_open: u8`.

**Earlier (now-obsolete) blocker-node design, kept for context:** spawn a hidden bare-Node blocker at scene-load time and toggle Visibility. Was correct for "block everything" semantics but is the wrong semantics per Frank's per-rect requirement.

**Cleanup of failed attempts:** keep panel `GlobalZIndex(51)` (Attempt 1, correct); remove the imperative blocker spawn/despawn from all four executor arms (Attempt 2); keep+extend the targeting guard (Attempt 3, correct).

**Latent debt:** the six executor panel arms (Open/Close x Inventory/Shop/Container) + ToggleInventory duplicate near-identical `panel_open`/blocker/`ui.panel_opened` bookkeeping and have ALREADY drifted (ToggleInventory duplicates the spawn block). A single `set_panel_open(...)` helper would prevent further drift.
